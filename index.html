OneBook

OneBook is institutional buy-side investment infrastructure for asset managers, funds, hedge funds, family offices, and proprietary investment teams. It connects research and systematic signals with scenario analysis, IBOR/PMS portfolio state, risk and constraints, approvals, and OMS order workflows.

Rather than replacing existing systems of record, it provides a governed decision layer across data, research, PMS, OMS, risk, and execution — preserving point-in-time context, lineage, permissions, and outcomes from thesis and signal generation through post-trade review.

Odysseus

Odysseus is a local-first control plane for coding agents, Git worktrees, and tmux sessions. It coordinates agent work through durable queues, isolated branches, review gates, and auditable evidence while keeping the terminal first-class.

The goal is to make AI coding agents operationally useful: plan work before spending tokens, run parallel tasks safely, surface only the decisions that need human attention, and preserve enough context to review what happened.

What I am thinking about

AI is becoming cheap and plentiful. The hard part is moving from an answer to a useful decision: asking a worthwhile question, using data you can actually trust, and building a workflow that survives contact with reality.

In finance, the model is only one piece of the system. The less visible parts — data lineage, point-in-time correctness, validation, portfolio construction, execution, risk, and knowing when to do nothing — usually decide whether the result is useful.

The same applies to most serious software. A good system should not merely produce an answer. It should preserve the evidence, assumptions, uncertainty, constraints, and consequences behind the decision.
